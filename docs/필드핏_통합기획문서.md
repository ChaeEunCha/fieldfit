# Ⅰ. 문제 정의 및 시장 분석

## 1. 문제 정의

### 1.1 문제 현상과 원인 (표면 → 근본원인)

**현상**: 서울에서 귀농한 초보 농업인 A씨가 표준 생장 지식("25~30°C, 물 관리 중요")만 믿고 재배를 시작했다가, 고창 지역 특유의 토양(황토, 산도)과 봄철 야간 저온을 고려하지 못해 초기 뿌리 활착에 실패함.

**원인 구조를 5Whys로 분해하면 다음과 같습니다.**

| 단계 | 질문 | 답 |
|---|---|---|
| Why 1 | 왜 초기 정착(재배)에 실패했는가? | 재배지의 실제 환경(토양·기후)에 맞지 않는 작물/시기를 선택했기 때문 |
| Why 2 | 왜 환경에 안 맞는 선택을 했는가? | 전국 공통 "표준 생육 매뉴얼"만 참고했고, 지역 고유의 토양·기상 변수를 반영하지 못했기 때문 |
| Why 3 | 왜 지역 변수를 반영하지 못했는가? | 흙토람·기상청 등 관련 데이터가 기관별로 흩어져 있고, pH·EC·유효인산 같은 전문 용어라 해석이 어렵기 때문 |
| Why 4 | 왜 해석이 어려운가? | 데이터를 "내 땅에 이 작물이 맞는지"로 변환해주는 진단 도구나 전문가 접근성이 초보 귀농인에게는 부족하기 때문 |
| Why 5 | 왜 그런 도구가 없는가? | 기존 농업 서비스(그린대로, 팜모닝 등)는 정책·시세·커뮤니티 정보 제공에 특화되어 있고, **개인화된 환경-작물 적합도 정량 진단**은 시장에 빈 영역으로 남아 있기 때문 |

→ **근본 원인**: "표준 매뉴얼과 실제 재배지 환경 사이의 정보 격차"를 메워줄, 지역·시기 특화 진단 도구의 부재.

### 1.2 JTBD(Jobs To Be Done) 분석

| 구분 | 내용 |
|---|---|
| Functional Job(기능적 과업) | 내 땅·지역의 토양·기후 데이터를 기반으로 "이 작물을 지금 심어도 되는지" 판단하고, 저온·병해 등 위험 시점을 미리 알고 싶다 |
| Emotional Job(정서적 과업) | 표준 매뉴얼만으로는 알 수 없는 리스크에 대한 불안을 줄이고, 첫 재배 성공에 대한 확신을 얻고 싶다 |
| Social Job(사회적 과업) | 주변(가족, 지역 농업인 커뮤니티)에게 "준비된 귀농인"으로 인정받고 싶다 |

**Job Statement**: "내가 정착한 지역에서 첫 작물을 심으려 할 때, 표준 매뉴얼이 아니라 내 땅과 날씨에 맞춘 판단 근거를 얻고 싶다. 그래야 초기 실패로 인한 경제적 손실과 정착 좌절을 피할 수 있다."

이 Job은 8장의 요구사항 ②(환경 적합도 산출), 특히 "시계열/예측 데이터 처리"(야간 저온 3일 예상 등 선제 경고)와 직접 연결됩니다 — A씨 실패 사례의 핵심 원인이 바로 이 지점이기 때문입니다.

## 2. 가설 수립

분석 과정에서 도출한 니즈 기반 가설은 다음과 같습니다.

### 가설 1. 초보 귀농인은 표준 재배 매뉴얼만으로 자기 지역의 실제 리스크를 판단하기 어려워한다.
- **근거**: 위 A씨 사례, 5Whys 분석 결과
- **검증 필요 자료**: 귀농귀촌 실태조사(정착 인프라 관련 항목), 귀농인 대상 정성 인터뷰

### 가설 2. 귀농 인구는 늘고 있지만, 정부 정책 자체가 "양적 확대"에서 "질적 정착"으로 방향을 틀고 있어, 개인화 진단 서비스에 대한 수요 기반이 형성되고 있다.
- **근거**: 2025년 귀농 가구는 8,735가구(전년 대비 6.0%↑), 귀농 인구는 9,134~11,617명 수준(자료별 상이)으로 전년보다 8.5~8.7% 증가했으며, 특히 70대 이상 고령층과 여성의 귀농이 역대 최대 비중을 기록함(농림축산식품부·해양수산부·국가데이터처, 2025년 귀농어·귀촌인 통계). 한 관련 보도는 귀농 정책의 방향이 "정착 지원금 규모"가 아니라 "얼마나 살기 좋은 인프라를 갖췄는가", 즉 정착의 질로 옮겨가고 있다고 지적합니다.
- **시사점**: 정부도 개별 맞춤형 정보 제공(그린대로 등)에 투자하고 있지만, "작물×토양×기후"를 계산해주는 진단 로직까지는 다루지 않아 민간 서비스가 채울 여지가 있음.

### 가설 3. 기존 농업 플랫폼은 "정보 통합·커뮤니티"에는 강하지만 "내 땅+내 작물"에 대한 정량적 적합도 진단 기능은 제공하지 않아, 이 영역이 공백 시장이다.
- **근거(벤치마킹)**:
  - **팜모닝(그린랩스)**: 국내 1위 농민 플랫폼으로 출시 1년 8개월 만에 60만 회원을 넘겼고 현재 90만 이상 회원을 보유. 실사용 조사에서 이용자들이 가장 많이 쓰는 기능은 "숨은 보조금"(60%), "병해충 정보"(35%), "농약 정보"(26%) 순으로 나타났으며, 이는 시세·보조금·커뮤니티 중심 서비스임을 보여줌. 반면 "내 지역 토양·기후에 이 작물이 맞는가"를 계산해주는 기능은 확인되지 않음.
  - **그린대로(농림축산식품부)**: 농지·주거·일자리·교육 등 55만 건의 정보를 개인 맞춤형으로 통합 제공하는 정부 플랫폼이지만, 정책/인프라 정보 중심이며 작물별 환경 적합도 진단 기능은 없음.
- **시사점**: 두 대표 서비스 모두 "정보 접근성"은 해결했지만 "판단(진단)"까지는 넘어가지 않았다는 공백이 확인됨 → 필드핏의 차별화 지점.

### 가설 4. 고령층·겸업 귀농 비중 증가로 농업 경험이 얕은 신규 귀농인이 늘고 있어, 진입장벽을 낮추는 "쉬운 설명형" 도구에 대한 수요가 커지고 있다.
- **근거**: 2025년 통계에서 70대 이상 고령층과 여성 귀농이 역대 최대 비중을 기록했고, 겸업(다른 직업과 병행) 귀농 비중이 32.6%에 달함 — 이는 전업 농업인 대비 상대적으로 농업 전문성이 낮은 신규 유입층이 늘고 있음을 시사.
- **검증 필요**: 연령대별/겸업 여부별 재배 실패 경험 설문 또는 지자체 귀농지원센터 상담 사례 확보

| **SAM** | 귀농·귀촌인 대상 정보/진단 서비스 시장 | 2025년 기준 귀촌 41.3만 명 + 귀농 9,134~11,617명 등 매년 신규 유입되는 귀농·귀촌 인구 및 기존 정착 3년 이내 인구(누적 수십만 명 규모) | 농림축산식품부·해양수산부·국가데이터처, 2025년 귀농어·귀촌인 통계 |

> ⚠️ 확정 통계 관련 유의사항: 2025 농림어업총조사의 확정 귀농귀촌 인구 통계는 2026년 4월 이후 국가데이터처를 통해 공식 발표될 예정이므로, 위 수치는 잠정치·언론 발표치 기준이며 이후 갱신이 필요합니다.

### 3.2 시장 성장률
- 국내 스마트팜/농업기술 시장: 2020년~2025년 연평균 약 15~16% 성장
- 귀농 인구: 2025년 전년 대비 8.5~8.7% 증가(귀촌은 오히려 0.5~2.2% 감소 — "귀촌은 줄고 귀농은 느는" 구조적 변화)
- 세계 스마트팜 시장: 2022~2026년 연평균 약 7% 성장(BIS Research 기준)

### 3.3 시장 동인 (Market Drivers)
1. **기후변화로 인한 재배 환경 불확실성 증가**: 이상기후로 표준 매뉴얼과 실제 환경 간 괴리가 커지고 있음.
2. **베이비부머 은퇴 + 고령/여성 귀농 확대**: 농업 경험이 얕은 신규 유입층 증가 → 쉬운 진단·설명 도구 수요 증가.
3. **정부 정책 기조 전환**: "귀농귀촌 양적 확대"에서 "정착률 제고(질적 정착)"로 정책 목표가 이동 중 → 데이터 기반 의사결정 지원 도구에 대한 정책적 관심 증가.
4. **공공데이터 개방 확대**: 흙토람 오픈API, 기상청 단기예보 API, 농경지화학성 통계 등 실시간 연동 가능한 데이터 인프라가 계속 확장되고 있음.
5. **생성형 AI 대중화**: LLM 비용 하락과 API 접근성 향상으로, 전문 용어(EC, 유효인산 등)를 일반인 언어로 변환하는 서비스 구현 장벽이 낮아짐.

|---|---|
| 귀농 인구 증가세 + 정책 기조가 "정착률 제고"로 전환 중이라 관련 도구에 대한 정책적 관심 커짐 | 그린대로 등 정부 플랫폼이 2단계 고도화를 통해 유사 진단 기능을 직접 추가할 가능성 |
| 공공데이터 개방 확대(오픈API 창구 지속 확충) | 팜모닝 등 대형 민간 플랫폼이 기능 확장을 통해 유사 서비스로 진입할 가능성 |
| 생성형 AI 비용 하락으로 소규모 팀도 고품질 자연어 리포트 구현 가능 | 흙토람/기상청 API의 안정성, 응답 지연, 데이터 결측 등 운영 리스크 |

### 4.3 경쟁 포지셔닝 요약
기존 서비스들은 "정보를 모아서 보여준다(그린대로)"거나 "커뮤니티·거래·시세를 지원한다(팜모닝)"는 축에 위치하는 반면, 필드핏은 "내 땅 + 내 작물 + 지금 시점"을 계산해 **적합도 점수와 위험 시점을 판단해준다**는 축(정보 제공 → 의사결정 지원)으로 차별화됩니다. 이는 경쟁이 없는 블루오션이라기보다는, 아직 아무도 정면으로 풀지 않은 "검증되지 않은 니즈"에 가깝기 때문에 MVP 단계에서 실사용자 반응 검증이 중요합니다.

### 6.1 문제 요약
초보 귀농인은 전국 공통 표준 생육 매뉴얼만 참고해 재배를 시작하고, 정작 실패의 결정적 원인이 되는 지역 고유의 토양(pH·EC·유효인산)·기상(야간 저온 등) 변수는 반영하지 못한다. 흙토람·기상청 데이터가 공개돼 있어도 전문 용어라 해석이 어렵고, 이를 "내 땅에 이 작물이 맞는지"로 변환해주는 도구가 없다. (상세 근거: 1장 문제 정의, 2장 가설 수립)

### 6.2 해결 방안
1. 기상청 단기예보·농경지 토양정보를 작물별 표준 생육조건(온도·pH)과 대조해 **정량 적합도 점수**를 산출 (→ 8장, 18~19장)
2. LLM으로 전문 데이터를 **자연어 재배 가이드 리포트**로 변환 (→ 16장, 22장)
3. 위험 시점을 **캘린더(.ics)**로 미리 알려 선제 대응 가능하게 함 (→ 17장, 20장)
4. 리포트를 근거로 후속 질문에 답하는 **컨텍스트 챗봇** 제공 (→ 17장, 22장)

## 8. 기술 스택 및 아키텍처

### 8.1 기술 스택
| 영역 | 기술 |
|---|---|
| 프론트엔드 | Next.js / React |
| 데이터 소스 | 공공데이터포털(data.go.kr) Open API — 기상청 단기예보 조회서비스, 농경지 토양정보(농경지화학성 통계) |
| 작물 기준 데이터 | 작물별 표준 생육조건 DB (사과·배·오이·감자·상추) — 18장 기준값 참고 |
| AI | LLM (예: Claude API) — 리포트 생성, 챗봇 응답 |
| 자동화/프로토타이핑 | Google Apps Script — 공공데이터 수집·가공 자동화 스크립트(프로토타입 단계) |
| 캘린더 연동 | .ics 캘린더 파일 생성 라이브러리 |

### 8.2 데이터 흐름 (실서비스 목표 아키텍처)
```
[사용자 입력: 지역·작물·재배 예정 시기]
        │
        ▼
[공공데이터 수집 계층]
  ├─ 기상청 단기예보 API  (기온·강수 등 시계열)
  └─ 농경지 토양정보 API (pH·EC·유효인산 등)
        │
        ▼
[환경 적합도 산출 엔진] ── 작물별 표준 생육조건 DB 대조 (18~19장)
        │
        ├─▶ [적합도 점수 / 5작물 비교 매트릭스]
        ├─▶ [위험 시점 판별 → .ics 캘린더 생성 + 알림 설정]
        └─▶ [LLM 리포트 생성]
                    │
                    ▼
            [컨텍스트 챗봇] (리포트를 근거로 Q&A)
```

### 8.3 예선 제출 단계 아키텍처 (실제 구현 범위)
> 예선 제출은 실제 개발 없이도 가능하며, 서비스가 어떤 문제를 어떻게 해결하는지 시각적으로 전달하는 것이 핵심입니다.

- 위 아키텍처의 API 연동·LLM 연동 부분은 **모두 더미데이터로 대체**
- Next.js/React로 화면 흐름만 구현한 클릭형 프로토타입 제작
- 백엔드 서버, 실제 Open API 호출, 실제 LLM 호출 **없음**

### 9.1 시연 화면 흐름 (요약)

2. 환경 적합도 결과: 점수 + 등급 + 핵심 리스크(저온) 노출
3. 5작물 비교 매트릭스: 동일 지역 기준 5작물 적합도 한눈에 비교

5. 위험 경고 캘린더: 저온 위험일 표시, 알림 시점 선택, .ics 다운로드
6. 컨텍스트 챗봇: 리포트 내용 기반 추가 질문("지금 심어도 되나요?" 등)

## 14. 사용자 플로우 (메인 시나리오 기준)

1. 사용자가 지역(예: 전북 고창)과 재배 예정 작물(예: 사과), 재배 예정 시기를 입력한다. (F1)
2. 서비스가 해당 지역의 기상 단기예보·토양정보를 "연동 중" 화면으로 보여준다. (F2)
3. 적합도 점수·등급·핵심 리스크 요약이 표시된다. (F3)
4. 사용자는 동일 지역 기준 5작물 비교 매트릭스로 다른 작물과 비교할 수 있다. (F4)
5. LLM 리포트가 생성되어 자연어 가이드로 제공된다. (F5)
6. 사용자는 리포트 하단 챗봇에 자연어로 추가 질문을 할 수 있다. (F6)
7. 사용자는 위험 경고 캘린더에서 저온 등 위험일을 확인하고, 알림 수신 시점(예: 1일 전/3일 전)을 선택한 뒤 .ics 파일을 다운로드한다. (F7, F8)

## 15. 기능 상세 명세

### F1. 온보딩 (지역·작물·시기 입력)
| 항목 | 내용 |
|---|---|
| 목적 | 적합도 산출에 필요한 최소 입력값 확보 |
| 입력 | 지역(시/군/읍면 단위 선택), 작물(5종 중 선택 또는 "전체 비교"), 재배 예정 시기(월 단위) |
| 처리 | 입력값을 다음 화면(F2)으로 전달 |
| 출력 | 입력 요약 카드 → 데이터 연동 화면 전환 |
| 예외 처리 | 필수값 미입력 시 진행 버튼 비활성화, 인라인 안내 문구 표시 |
| UI 요소 | 지역 검색/선택 드롭다운, 작물 카드 선택(아이콘형), 월 선택 슬라이더 또는 드롭다운 |

### F2. 공공데이터 연동 표시 (기상·토양)
| 항목 | 내용 |
|---|---|
| 목적 | "실시간 공공데이터 연동" 가치를 사용자에게 시각적으로 전달 |
| 데이터 소스(실서비스 기준) | 기상청 단기예보 조회서비스(기온·강수), 농경지 토양정보(농경지화학성 통계: pH·EC·유효인산 등) |
| 처리(프로토타입) | 실제 API 호출 없이, 선택된 지역에 매핑된 더미 JSON을 2~3초 로딩 애니메이션과 함께 표시 |
| 출력 | "○○ 지역 기상 데이터 조회 완료", "토양 성분 데이터 조회 완료" 등 단계별 체크 애니메이션 |
| 예외 처리(실서비스 기준) | API 응답 지연·결측 시 최근 캐시 데이터 또는 지역 평균값 대체 안내 (20.4절 데이터 결측 정책 참고) |

### F3. 환경 적합도 산출 결과
| 항목 | 내용 |
|---|---|
| 목적 | 작물별 표준 생육조건(온도·pH) 대비 현재 지역·시기 환경의 정량 적합도 제공 |
| 입력 | F1의 지역·작물·시기, F2의 기상/토양 데이터 |
| 처리 | 19장의 적합도 산출 공식에 따라 점수(0~100) 및 등급 산정 |
| 출력 | 종합 적합도 점수, 등급(매우적합~부적합), 세부 항목별 점수(온도 적합도/토양 적합도), 핵심 리스크 요약 1~2줄 |
| UI 요소 | 원형 게이지(종합 점수), 항목별 막대그래프, 리스크 배지(예: "⚠ 야간 저온 주의") |
| 프로토타입 데이터 | 페르소나 시나리오(고창·사과)에 맞춘 더미 점수 세트 사전 정의 |

### F4. 5작물 환경 적합도 비교 매트릭스
| 항목 | 내용 |
|---|---|
| 목적 | 동일 지역 기준으로 5작물(사과·배·오이·감자·상추)의 적합도를 한눈에 비교 |
| 입력 | F1의 지역·시기 (작물은 전체 5종 고정 비교) |
| 처리 | 5작물 각각에 대해 F3과 동일한 산출 로직 적용 |
| 출력 | 매트릭스 표(작물 × 적합도 점수/등급) 또는 레이더 차트, 정렬(적합도 높은 순) 가능 |
| UI 요소 | 표/카드 토글, 작물 클릭 시 F3 상세 결과로 이동 |
| 활용 페르소나 | 서브 페르소나(박은주) — 작물·지역 미확정 예비 정착민의 비교 탐색 니즈 충족 |

### F5. LLM 재배 가이드 리포트
| 항목 | 내용 |
|---|---|
| 목적 | 전문 용어(pH, EC, 유효인산 등)를 초보자가 이해할 수 있는 자연어 가이드로 변환 |
| 입력(실서비스 기준) | F3 적합도 산출 결과(점수, 세부 항목, 리스크), 작물별 표준 생육조건 |
| 처리(실서비스 기준) | LLM(Claude API 등)에 산출 데이터를 프롬프트로 전달해 리포트 생성 |
| 처리(프로토타입) | 사전 작성된 더미 리포트 텍스트를 "리포트 생성 중..." 연출 후 노출 |
| 출력 | 리포트 섹션 구성 — ① 종합 진단 요약 ② 토양·기후 상세 설명(쉬운 말로) ③ 시기별 재배 가이드 ④ 주의해야 할 리스크와 대응법 |
| UI 요소 | 리포트 카드형 레이아웃, 섹션별 아코디언, 하단 "챗봇에게 더 물어보기" CTA |

### F6. 컨텍스트 챗봇
| 항목 | 내용 |
|---|---|
| 목적 | 생성된 리포트를 근거로 사용자의 후속 자연어 질문에 답변 |
| 입력(실서비스 기준) | 사용자 질문 + F5 리포트 전문(컨텍스트로 주입) |
| 처리(실서비스 기준) | LLM에 리포트를 컨텍스트로 포함해 질의응답 (응답 범위는 22.2절 챗봇 응답 정책 참고) |
| 처리(프로토타입) | 예상 질문 3~5개(예: "지금 심어도 되나요?", "언제가 제일 위험한가요?", "다른 작물은 어때요?")에 대한 더미 답변 세트를 미리 준비, 실제 LLM 호출 없이 매칭 응답 |
| 출력 | 채팅형 UI, 답변 하단 "리포트 ○○ 항목 근거" 태그 표시 |
| 예외 처리(실서비스 기준) | 리포트 범위를 벗어난 질문에는 "리포트 근거 밖의 질문"임을 명시하고 일반 안내로 전환 |

### F7. 위험 경고 캘린더 (.ics)
| 항목 | 내용 |
|---|---|
| 목적 | 저온·병해 등 위험 시점을 캘린더로 선제 안내 |
| 입력(실서비스 기준) | 기상청 단기예보 시계열, 작물별 위험 기준(18장, 20장) |
| 처리(프로토타입) | 페르소나 시나리오 기준 더미 위험일자(예: 야간 저온 예상일 2~3일)를 사전 정의 |
| 출력 | 캘린더 뷰에 위험일 하이라이트 + 위험 유형 배지, ".ics 다운로드" 버튼 |
| 기술 구현 | .ics 파일 생성은 클라이언트 사이드에서 실제로 동작하도록 구현(더미 위험일자 기준) — 시연 시 실제 캘린더 앱에 등록 가능함을 보여줄 수 있음 |
| 예외 처리 | 위험일 없음 시 "현재 예보 기준 위험 시점 없음" 안내 |

### F8. 알림 수신 시점 설정
| 항목 | 내용 |
|---|---|
| 목적 | 사용자가 원하는 시점에 위험 경고를 받을 수 있도록 커스터마이징 |
| 입력 | 알림 시점 옵션 선택(당일/1일 전/3일 전 등, 상세는 20.3절) |
| 처리(프로토타입) | 선택값을 .ics 이벤트의 알림(VALARM) 설정에 반영 |
| 출력 | 선택 완료 토스트, .ics 파일에 알림 시간 반영 |
| 실서비스 확장 | 이메일/푸시 알림 발송 채널 추가 (예선 프로토타입 범위 밖) |

### F9. 마이페이지 / 진단 이력 (Should/Could)
| 항목 | 내용 |
|---|---|
| 목적 | 과거 진단 기록 확인, 재방문 유도 |
| 처리(프로토타입) | 더미 이력 리스트(2~3건) 표시 |
| 우선순위 | 예선 시연에는 필수 아니며, 시간 여유 시 구현 |

### F10. 밭 구역 관리 (게임화 시각화)
| 항목 | 내용 |
|---|---|
| 목적 | 사용자가 재배 예정지를 구역 단위로 나눠 어디에 무엇을 심었는지 배치·관리하고, 구역별 상태를 한눈에 파악하게 함 |
| 입력 | 구역 탭 → 진단 완료된 작물 목록 중 선택 |
| 처리(프로토타입) | 대시보드 화면에 구역 그리드를 통합 표시. 구역 탭 시 작물 선택 시트가 뜨고, 선택 결과가 클라이언트 상태로 즉시 구역에 반영됨(서버 저장 없음). 구역 상태(정상/주의/위험)는 F7의 더미 위험 이벤트 `cropsAffected`에 해당 구역 작물이 포함되면 자동으로 주의/위험으로 산정 |
| 출력 | 구역별 작물 아이콘 + 상태 색상(정상/주의/위험) 그리드, 빈 구역은 "+" 표시 |
| UI 요소 | 그리드 타일(구역), 작물 선택 시트/모달, 상태 배지(위험 경고 캘린더와 동일한 배지 톤 사용) |
| 예외 처리 | 진단 완료된 작물이 없으면 구역 배정 불가 안내 후 F1 온보딩으로 유도 |
| 실서비스 확장 | 별도 "내 밭 관리" 화면/모듈로 분리, 실좌표·실면적 기반 구역 정의, 서버에 배치 상태 저장 |

## 18. 작물별 표준 생육조건 기준값

> 아래 수치는 일반 원예·농업 기술 자료(농촌진흥청 표준영농교본 등 공개 자료 기준)를 참고한 **잠정 기준치**입니다. 실서비스 전환 시 농촌진흥청 농사로·표준영농교본 최신판 수치로 검증·갱신이 필요합니다.

| 작물 | 생육 적정온도 | 저온 위험 기준 | 고온 위험 기준 | 적정 토양 pH | 비고 |
|---|---|---|---|---|---|
| 사과 | 15~25°C | 개화기 최저기온 -2°C 이하 | 생육기 33°C 이상 지속 | 5.5~6.5 | 개화기(4월경) 서리 피해에 특히 취약 |
| 배 | 15~25°C | 개화기 최저기온 -1.7°C 이하 | 생육기 33°C 이상 지속 | 5.5~6.5 | 사과와 유사하나 개화 시기가 약간 빠름 |
| 오이 | 18~28°C (야간 13~15°C) | 10°C 이하 생육 정지 | 30°C 이상 착과 불량 | 5.5~6.8 | 저온에 특히 민감, 정식 초기 보온 필요 |
| 감자 | 14~20°C | 서리 피해 0°C 이하 | 25°C 이상 괴경 비대 저하 | 5.0~6.0 | 약산성 선호(더뎅이병 예방), pH 6.5 초과 시 병해 위험 상승 |
| 상추 | 15~20°C | 5°C 이하 생육 저하 | 25°C 이상 추대(꽃대) 발생 위험 | 6.0~6.8 | 서늘한 기후 선호, 고온기 재배 시 추대 관리 필요 |

### 18.1 기준값 데이터 소스 (실서비스 목표)
- 작물별 표준 생육조건 DB: 농촌진흥청 표준영농교본, 농사로 작물별 재배정보
- 토양 pH 등 현재값: 농경지 토양정보(농경지화학성 통계) — 흙토람/공공데이터포털
- 기온 예보값: 기상청 단기예보 조회서비스

## 19. 환경 적합도 산출 정책

### 19.1 산출 항목 및 가중치
| 항목 | 가중치 | 산출 방식 |
|---|---|---|
| 온도 적합도 | 60% | 예보 기온(또는 재배 예정 시기의 평년 기온)이 작물별 생육 적정온도 범위에 드는 정도 |
| 토양 적합도 | 40% | 현재 농경지 pH가 작물별 적정 pH 범위에 드는 정도 |

> 종합 적합도 점수 = (온도 적합도 점수 × 0.6) + (토양 적합도 점수 × 0.4)

### 19.2 항목별 점수 산정 규칙 (0~100점)
- **범위 내**: 적정 범위 안에 있으면 **100점**
- **범위 이탈**: 적정 범위를 벗어난 만큼 점수를 차감
  - 예: 온도가 적정 하한보다 낮을 경우, `100 - (차이 폭 × 감점 계수)`로 계산하며, 차이가 클수록 점수가 급격히 낮아지도록 설계
  - 위험 기준(저온/고온 위험 기준, 18장 표 참고)을 초과하는 경우 해당 항목 점수는 **20점 이하**로 처리
- 프로토타입 단계에서는 위 규칙을 적용해 사전 계산한 값을 더미데이터로 사용(17.1, 17.2절 스키마 참고)

### 19.3 등급 구간
| 점수 구간 | 등급 | 의미 |
|---|---|---|
| 85~100 | 매우적합 | 지금 조건에서 재배 시작을 적극 권장 |
| 70~84 | 적합 | 재배 가능, 특이사항 없음 |
| 50~69 | 보통 | 재배 가능하나 일부 리스크 요인 존재, 리포트의 주의사항 확인 필요 |
| 30~49 | 주의 | 재배 시 위험 요인이 뚜렷함, 시기 조정 또는 대응 조치 권장 |
| 0~29 | 부적합 | 현재 조건에서는 재배를 권장하지 않음 |

### 19.4 5작물 비교 매트릭스 정책
- 동일 지역·동일 시기 기준으로 5작물 각각에 위 19.1~19.3 규칙을 동일하게 적용
- 정렬 기본값: 적합도 점수 높은 순
- 동점 처리: 온도 적합도 점수가 높은 작물을 상위로 정렬

## 20. 위험 경고 및 알림 정책

### 20.1 위험 유형 정의
| 위험 유형 | 트리거 조건 | 대상 작물 예시 |
|---|---|---|
| 저온 위험 | 예보 최저기온이 작물별 저온 위험 기준 이하로 예상 | 사과·배(개화기), 오이(정식 초기) |
| 고온 위험 | 예보 최고기온이 작물별 고온 위험 기준 이상으로 지속 예상(2일 이상) | 오이(착과 불량), 감자(괴경 비대 저하), 상추(추대) |
| 토양 병해 위험 | 토양 pH가 작물 적정 범위를 벗어나 병해 발생 가능성 상승(예: 감자 pH 6.5 초과 시 더뎅이병) | 감자 |

### 20.2 위험 경고 캘린더(.ics) 생성 규칙
- 위험 유형별로 예보 기간 내 해당 일자를 이벤트로 생성
- 이벤트 제목 형식: `[필드핏] {작물} {위험유형} 주의 — {지역}`
- 이벤트 설명: 리포트에서 발췌한 근거 1줄 포함
- 다중 위험이 겹치는 날짜는 하나의 이벤트로 병합하고 위험 유형을 모두 나열

### 20.3 알림 수신 시점 옵션
| 옵션 | 설명 |
|---|---|
| 당일 | 위험 발생 당일 오전 알림 |
| 1일 전 | 위험 발생 1일 전 알림 (기본값) |
| 3일 전 | 위험 발생 3일 전 알림 |
| 7일 전 | 위험 발생 7일 전 알림(장기 예보 신뢰도 낮음 — 참고용으로 표시) |

- 사용자가 선택한 옵션은 .ics 이벤트의 VALARM(알림) 속성에 반영
- 7일 전 옵션 선택 시 "단기예보 특성상 정확도가 낮을 수 있음" 안내 문구 표시

### 20.4 데이터 결측·지연 시 처리 원칙 (실서비스 목표)
- API 응답 지연·오류 시: 직전 캐시 데이터 사용 + "최신 데이터 조회 실패, ○○ 기준 데이터로 안내" 명시
- 토양 데이터 자체가 없는 지역: 인접 행정구역 평균값으로 대체하고 "인근 지역 데이터 기반 추정치" 명시
- 프로토타입 단계: 결측 상황을 실제로 다루지 않으며, 정상 조회된 상태의 화면만 시연

## 21. 데이터 정책

### 21.1 데이터 갱신 주기 (실서비스 목표)
| 데이터 | 갱신 주기 | 비고 |
|---|---|---|
| 기상청 단기예보 | 3시간 단위(기상청 발표 주기에 맞춤) | 최신 발표 시각 기준 재계산 |
| 농경지 토양정보(농경지화학성 통계) | 연 1회 수준(원자료 갱신 주기에 따름) | 최근 조사연도 기준값 사용, 화면에 조사연도 명시 |
| 작물별 표준 생육조건 DB | 비정기(기준 자료 개정 시) | 농촌진흥청 자료 개정 시 갱신 |

### 21.2 개인정보·데이터 이용 정책
- 예선 프로토타입 단계에서는 실제 회원가입·위치정보·개인정보를 수집하지 않음(모든 입력은 세션 내 임시값)
- 실서비스 전환 시 위치정보(재배지 주소)는 적합도 산출 목적으로만 사용하며, 별도 개인정보처리방침 수립 및 이용자 동의 절차 필요

## 22. LLM 리포트 및 챗봇 응답 정책

### 22.1 리포트 생성 원칙
- 리포트는 F3 적합도 산출 결과(점수, 세부 항목, 위험 유형)를 **입력 근거로만** 사용해 생성 — 산출 로직에 없는 내용을 리포트가 임의로 추가하지 않음
- 전문 용어(pH, EC, 유효인산 등)는 반드시 쉬운 말로 1회 이상 풀어서 설명
- 리포트 말미에 "본 리포트는 참고용 정보이며 최종 재배 판단은 사용자에게 있음"을 명시(면책 조항, 22.3절 참고)

### 22.2 챗봇 응답 범위 정책
- 챗봇은 **직전에 생성된 리포트 내용을 근거로만** 답변 (리포트에 없는 새로운 지역·작물 진단을 임의로 생성하지 않음)
- 리포트 범위를 벗어난 질문(예: 병충해 방제 농약 처방 등 전문 영역): "본 서비스의 리포트 근거 범위를 벗어난 질문"임을 안내하고, 필요 시 농촌진흥청 상담 채널 등 외부 자원 안내로 대체
- 답변 시 근거가 된 리포트 섹션을 태그로 표시(예: "종합 진단 요약" 근거) — F6 참고
- 의료·법률적 확정 진단처럼 단정적 표현(반드시 ~하세요) 대신 권고형 표현(~를 권장합니다) 사용

### 22.3 면책 조항 (실서비스 목표 문구안)
> "필드핏이 제공하는 적합도 점수, 리포트, 위험 경고는 공개된 공공데이터와 표준 생육조건을 기반으로 한 참고용 정보이며, 실제 재배 결과(수확량, 병해 발생, 경제적 손실 등)를 보장하지 않습니다. 최종 재배 의사결정과 그에 따른 책임은 사용자 본인에게 있으며, 중요한 의사결정 전에는 지역 농업기술센터 등 전문가 상담을 병행할 것을 권장합니다."

- 위 문구는 리포트 화면 하단 및 서비스 이용약관에 상시 노출
- 예선 프로토타입에서도 리포트 화면 하단에 면책 문구를 시각적으로 포함해 실서비스 수준의 완성도를 시연
